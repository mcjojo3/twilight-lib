    TWILIGHT LIB - BLOCKBENCH ADDON MODEL CONVERSION TUTORIAL
═══════════════════════════════════════════════════════════════════════════════

This tutorial explains how to convert Blockbench exported models into working
player addons for the Twilight Lib addon system.

═══════════════════════════════════════════════════════════════════════════════
STEP 1: CREATE YOUR MODEL IN BLOCKBENCH
═══════════════════════════════════════════════════════════════════════════════

1. Open Blockbench and create a new "Java Entity" model
2. Create or use the following groups (folders) for body parts:
   - Head
   - Body
   - Right Arm
   - Left Arm
   - Right Leg
   - Left Leg

   NOTE: You don't need all groups - only create the ones where you want
   addon parts to appear. For example, a tail would only use the "Body" group.

3. Add your custom model elements (e.g., horns in Head, tail in Body, wings in Body)
4. Texture your model
5. Export as "Java Entity" format and save the .java file

═══════════════════════════════════════════════════════════════════════════════
STEP 2: PLACE THE EXPORTED FILE
═══════════════════════════════════════════════════════════════════════════════

1. Save the exported .java file to:
   twilight-lib-1.20.1-forge/src/main/resources/assets/twilight_lib/models/

   Example: playerTail.java, playerHorns.java, etc.

═══════════════════════════════════════════════════════════════════════════════
STEP 3: PREPARE YOUR TEXTURE
═══════════════════════════════════════════════════════════════════════════════

1. Export your texture from Blockbench as a PNG file
2. Place it in:
   twilight-lib-1.20.1-forge/src/main/resources/assets/twilight_lib/textures/addon/

   Example: player_tail.png, player_horns.png, etc.

   The texture path will be: twilight_lib:textures/addon/YOUR_TEXTURE_NAME.png

═══════════════════════════════════════════════════════════════════════════════
STEP 4: CONVERT THE EXPORTED MODEL
═══════════════════════════════════════════════════════════════════════════════

The Blockbench export needs several modifications to work with Twilight Lib.

KEY IMPROVEMENTS IN THIS SYSTEM:
────────────────────────────────────────────────────────────────────────────
✓ Only define body parts you actually use (tail = Body only, horns = Head only)
✓ BaseAddonModel handles all rendering and syncing automatically
✓ No need to manually write getters, setupAnim, or renderToBuffer
✓ Safe loading - missing parts won't cause crashes

EXAMPLE CONVERSION (playerTail.java -> PlayerTailModel.java):

BEFORE (Blockbench export):
──────────────────────────────────────────────────────────────────────────────

    private final ModelPart Head;
    private final ModelPart Body;
    private final ModelPart Right Arm;  // ⚠️ SPACES IN NAME
    ...
}

═══════════════════════════════════════════════════════════════════════════════
SIMPLIFIED METHOD (RECOMMENDED - Using BaseAddonModel):
═══════════════════════════════════════════════════════════════════════════════

package mc.sayda.twilight_lib.client.model.addon;

import mc.sayda.twilight_lib.TwilightLib;
import net.minecraft.client.model.geom.ModelLayerLocation;
import net.minecraft.client.model.geom.ModelPart;
import net.minecraft.client.model.geom.PartPose;
import net.minecraft.client.model.geom.builders.*;
import net.minecraft.resources.ResourceLocation;
import net.minecraft.world.entity.Entity;

public class PlayerTailModel<T extends Entity> extends BaseAddonModel<T> {
    public static final ModelLayerLocation LAYER_LOCATION = new ModelLayerLocation(
        new ResourceLocation(TwilightLib.MODID, "player_tail"), "main");

    public PlayerTailModel(ModelPart root) {
        // Only get the parts you actually use!
        this.body = getChildSafe(root, "Body");  // Tail attached to body
        // For horns: this.head = getChildSafe(root, "Head");
        // For wings: this.body = getChildSafe(root, "Body");
    }

    public static LayerDefinition createBodyLayer() {
        MeshDefinition meshdefinition = new MeshDefinition();
        PartDefinition partdefinition = meshdefinition.getRoot();

        // Copy the part definition from Blockbench export
        PartDefinition Body = partdefinition.addOrReplaceChild("Body",
            CubeListBuilder.create()
                .texOffs(0, 0)
                .addBox(-2.0F, 8.0F, 2.0F, 4.0F, 4.0F, 10.0F, new CubeDeformation(0.0F)),
            PartPose.offset(0.0F, 0.0F, 0.0F));

        return LayerDefinition.create(meshdefinition, 64, 64);
    }
    // That's it! BaseAddonModel handles setupAnim, renderToBuffer, and getters
}

BENEFITS OF BaseAddonModel:
• Only ~20 lines of code instead of ~90
• Automatically handles rendering of all your parts
• No manual getter methods needed
• Safe loading - missing parts won't crash
• Perfect for most addon use cases

package mc.sayda.twilight_lib.client.model.addon;

import com.mojang.blaze3d.vertex.PoseStack;
import com.mojang.blaze3d.vertex.VertexConsumer;
import mc.sayda.twilight_lib.TwilightLib;
import net.minecraft.client.model.EntityModel;
import net.minecraft.client.model.geom.ModelLayerLocation;
import net.minecraft.client.model.geom.ModelPart;
import net.minecraft.client.model.geom.PartPose;
import net.minecraft.client.model.geom.builders.*;
import net.minecraft.resources.ResourceLocation;
import net.minecraft.world.entity.Entity;

public class PlayerTailModel<T extends Entity> extends EntityModel<T> {
    public static final ModelLayerLocation LAYER_LOCATION =
        new ModelLayerLocation(
            new ResourceLocation(TwilightLib.MODID, "player_tail"), "main");

    private final ModelPart head;
    private final ModelPart body;
    private final ModelPart rightArm;
    private final ModelPart leftArm;
    private final ModelPart rightLeg;
    private final ModelPart leftLeg;

    public PlayerTailModel(ModelPart root) {
        this.head = root.getChild("Head");
        this.body = root.getChild("Body");
        this.rightArm = root.getChild("Right_Arm");  // ✓ UNDERSCORES
        this.leftArm = root.getChild("Left_Arm");
        this.rightLeg = root.getChild("Right_Leg");
        this.leftLeg = root.getChild("Left_Leg");
    }

    public static LayerDefinition createBodyLayer() {
        MeshDefinition meshdefinition = new MeshDefinition();
        PartDefinition partdefinition = meshdefinition.getRoot();

        // Keep all the part definitions from Blockbench export
        // Just replace "Right Arm" with "Right_Arm", etc.
        PartDefinition Head = partdefinition.addOrReplaceChild("Head", ...);
        PartDefinition Body = partdefinition.addOrReplaceChild("Body", ...);
        PartDefinition Right_Arm = partdefinition.addOrReplaceChild("Right_Arm", ...);
        PartDefinition Left_Arm = partdefinition.addOrReplaceChild("Left_Arm", ...);
        PartDefinition Right_Leg = partdefinition.addOrReplaceChild("Right_Leg", ...);
        PartDefinition Left_Leg = partdefinition.addOrReplaceChild("Left_Leg", ...);

        return LayerDefinition.create(meshdefinition, 64, 64);
    }

    @Override
    public void setupAnim(Entity entity, float limbSwing, float limbSwingAmount,
                         float ageInTicks, float netHeadYaw, float headPitch) {
        // Leave empty - animation handled by PlayerAddonLayer
    }

    @Override
    public void renderToBuffer(PoseStack poseStack, VertexConsumer vertexConsumer,
                               int packedLight, int packedOverlay,
                               float red, float green, float blue, float alpha) {
        head.render(poseStack, vertexConsumer, packedLight, packedOverlay, red, green, blue, alpha);
        body.render(poseStack, vertexConsumer, packedLight, packedOverlay, red, green, blue, alpha);
        rightArm.render(poseStack, vertexConsumer, packedLight, packedOverlay, red, green, blue, alpha);
        leftArm.render(poseStack, vertexConsumer, packedLight, packedOverlay, red, green, blue, alpha);
        rightLeg.render(poseStack, vertexConsumer, packedLight, packedOverlay, red, green, blue, alpha);
        leftLeg.render(poseStack, vertexConsumer, packedLight, packedOverlay, red, green, blue, alpha);
    }

    // ✓ ADD THESE GETTERS
    public ModelPart getHead() { return head; }
    public ModelPart getBody() { return body; }
    public ModelPart getRightArm() { return rightArm; }
    public ModelPart getLeftArm() { return leftArm; }
    public ModelPart getRightLeg() { return rightLeg; }
    public ModelPart getLeftLeg() { return leftLeg; }
}

REQUIRED CHANGES CHECKLIST:
────────────────────────────────────────────────────────────────────────────
☑ Add package declaration: package mc.sayda.twilight_lib.client.model.addon;
☑ Add all required imports (see example above)
☑ Rename class to match your addon (e.g., PlayerTailModel, PlayerHornsModel)

  - Descriptive name like "player_tail" instead of "playerrig"

  - "Right Arm" → "Right_Arm"
  - "Left Arm" → "Left_Arm"
  - "Right Leg" → "Right_Leg"
  - "Left Leg" → "Left_Leg"
☑ Use camelCase for field names (head, body, rightArm, etc.)
☑ Update root.getChild() calls to use underscored names
☑ Update addOrReplaceChild() calls to use underscored names
☑ Add getter methods for all body parts
☑ Leave setupAnim() empty (comment explaining why)

STEP 6: REGISTER YOUR ADDON
═══════════════════════════════════════════════════════════════════════════════

1. Open: src/main/java/mc/sayda/twilight_lib/addon/AddonInit.java

2. Add your addon registration in the registerAddons() method:

   AddonRegistry.registerAddon(
       "your_addon_id",                    // ID used in commands
       YourAddonModel.LAYER_LOCATION,      // Your model's LAYER_LOCATION
       YourAddonModel::createBodyLayer,    // Your model's createBodyLayer method
       new ResourceLocation(TwilightLib.MODID, "textures/addon/your_texture.png")
   );

EXAMPLE:

   AddonRegistry.registerAddon(
       "player_tail",
       PlayerTailModel.LAYER_LOCATION,
       PlayerTailModel::createBodyLayer,
       new ResourceLocation(TwilightLib.MODID, "textures/addon/player_tail.png")
   );

═══════════════════════════════════════════════════════════════════════════════
STEP 7: BUILD AND TEST
═══════════════════════════════════════════════════════════════════════════════

1. Build the project:
   ./gradlew build

2. Run the game and test your addon:
   /tl addon list                    # Should show your addon ID
   /tl addon equip your_addon_id     # Equip to yourself
   /tl addon equip your_addon_id @p  # Equip to nearest player

3. If the addon appears but doesn't move correctly, check that:
   - Body part groups in Blockbench match the standard names
   - You've added all the getter methods
   - Part definitions use underscored names

COMMON ISSUES AND SOLUTIONS
═══════════════════════════════════════════════════════════════════════════════

ISSUE: Compile errors about spaces in variable names
FIX: Replace all spaces with underscores in getChild() and addOrReplaceChild()

ISSUE: Addon doesn't appear in /tl addon list
FIX: Check that AddonInit.registerAddons() is called and your registration is added

ISSUE: Addon appears but doesn't move with player
FIX: Ensure getter methods are present and body part names match exactly

ISSUE: Texture is missing/purple-black checkerboard
FIX: Verify texture path matches exactly in AddonInit registration

ISSUE: Model appears offset or in wrong position
FIX: Check PartPose.offset() values in createBodyLayer() match intended positions

═══════════════════════════════════════════════════════════════════════════════
TIPS AND BEST PRACTICES
═══════════════════════════════════════════════════════════════════════════════

• Use descriptive addon IDs (e.g., "dragon_tail", "demon_horns", "angel_wings")
• Test each body part independently to ensure proper attachment
• Keep texture resolution at 64x64 or powers of 2 (128x128, 256x256)
• Empty body part groups (like Head) can be left with CubeListBuilder.create()
• Models sync with player animations automatically - no animation code needed
• Use CubeDeformation for slight size adjustments without modifying base model
